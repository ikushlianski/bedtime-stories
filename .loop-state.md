## Iteration 9 — CRITICAL: Missing snapshot endpoint
- **Bug:** Frontend `api.pipeline.snapshot(id)` called `GET /pipeline/status/:id` which returns pipeline status, not a run snapshot. The plan-review page read `snapshot.psychologist_plan_output` (undefined), leaving the page stuck on "Loading assessment" forever. There was NO backend endpoint returning the snapshot shape.
- **Fix:** Added `GET /pipeline/snapshot/:storyId` to the backend. Queries runSnapshots table, returns snake_case shape matching the frontend's RunSnapshot interface. Updated frontend `api.pipeline.snapshot()` to hit the new URL.
- **Rationale:** Without this, the entire human-review flow (plan review, text review) would have been dead — user couldn't approve anything.
- **Status:** Types check, ready for commit.

## Iteration 8 — Fix approve-plan/approve-text body mismatch
- **Bug:** Frontend `api.stories.approvePlan(id)` and `approveText(id)` sent no request body. Backend schema requires `{approved: boolean}` via Zod validation — would return 400 on the entire human-review flow.
- **Fix:** Frontend now sends `{approved: true}` by default. Added optional `approved` parameter for future "reject" flow. Return type updated to `Story` since the backend actually returns the updated row.
- **Status:** Types check, only 2 callers (plan-review, text-review pages) — both use default so no caller update needed.

## Iteration 7 — CRITICAL: Pipeline status response shape mismatch
- **Bug:** Backend returned `{storyId, status: "running"|"done"|"error"}` but frontend expected `{story_id, status: "running"|"completed"|"failed"|"pending", current_step, steps[]}`. Calling `status.steps.map(...)` on `undefined` would have crashed the React page.
- **Fix:** Backend now returns the full expected shape. Maps internal status (`done`→`completed`, `error`→`failed`, `unknown`→`pending`). Returns a `steps[]` array populated with the five pipeline agents all sharing the coarse top-level status. Renames `storyId` → `story_id` to match frontend.
- **Rationale:** Coarse step status is imperfect but unblocks the UI. Per-step tracking can come later.
- **Status:** Types check, ready for commit.

## Iteration 6 — CRITICAL: Fix broken "Create Story" → pipeline wiring
- **Bug 1:** `handleCreateStory` in story-list.tsx created a story but NEVER called the pipeline. User clicks "Create Story", story is created in draft, navigated to pipeline page, nothing happens. This alone would have killed tomorrow morning's workflow.
- **Bug 2:** `api.pipeline.run` in lib/api.ts only sent `{ storyId }` but backend schema requires `{ storyId, seed }` — would have returned 400 even if called.
- **Fix:** Updated `api.pipeline.run(storyId, seed)` to accept and send seed. Updated `handleCreateStory` to call `api.pipeline.run(story.id, seed)` after creating. Only one caller existed in the codebase — no other breakage.
- **Rationale:** This is the single highest-impact find so far. Without it, every story creation would silently fail to produce content.
- **Status:** Types check, ready for commit.

## Iteration 5 — Retry logic for transient AI failures
- **Issue:** A single transient network hiccup (timeout, 503, rate limit) would kill the entire 6-agent pipeline. For a 10-minute run, that's catastrophic.
- **Fix:** Added 3-attempt retry with linear backoff (1.5s, 3s) in `runText`. `isRetryable` classifies by error message keywords (timeout, econn, network, 503, 504, 529, rate). Validation errors (bad JSON) are NOT retried since they'll fail the same way. Each retry logs attempt number and reason.
- **Rationale:** Observability without retries still leaves the pipeline fragile. Retries are cheap insurance against transient infrastructure issues.
- **Status:** Types check, ready for commit.

## Iteration 4 — AI runner observability
- **Issue:** `claudeCliRunner.runText` ran silently — no visibility into which agent is running, how long each call takes, or what failed. For a 6-agent pipeline, user sees minutes of silence then either success or an opaque failure.
- **Fix:** Added structured logging to runText: start line (label, model, prompt length), done line (duration, result length), error line (duration + error). `runStructured` passes a `label: skill:<name>` so each log line identifies the agent.
- **Rationale:** Observability is prerequisite for tomorrow-morning debugging. Didn't add retries yet — bigger change, separate iteration.
- **Status:** Types check, ready for commit.
